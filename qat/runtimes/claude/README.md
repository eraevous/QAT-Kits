# Claude skills from QAT-Kits

This repository is the source of record for the QAT skills Claude runs (DEC-192, DEC-193). The skills are generated from sources in this repo. Nobody uploads a hand-edited copy.

| What | Where |
|---|---|
| Source of each skill (edit this) | `qat/tools/<name>.skill.md`: frontmatter `name`, `version`, `description` (plus `kind: runner` for `qat`), then the skill text |
| Runner contracts (the `qat` skill carries them) | `qat/tools/*.qat.md`, `qat/cases/`, `qat/scripts/qat.py`, `qat/INDEX.md` |
| Generated skill (never edit) | `qat/runtimes/claude/<name>/SKILL.md` (and, for `qat`, the runner files beside it) |
| Versions and hashes of everything generated | `qat/runtimes/claude/skills.lock.json` (generated) |
| Bundle version (edit this when skills change) | `qat/runtimes/claude/BUNDLE_VERSION` |
| Generator, check and packager | `qat/scripts/skills.py` (standard library only) |

Each generated `SKILL.md` keeps the frontmatter Claude reads (`name`, `description`) and starts its body with one stamp line: `GENERATED by qat/scripts/skills.py from <source>`, the skill's version and the source's sha256. The stamp line costs a few tokens per load.

`kind-check/` and `real-problem/` in this folder are hand-adapted runtimes from before this scheme. They are not generated, not checked for staleness and not in the bundle. Porting them is a separate change.

## Commands (from the repo root)

    python3 -I qat/scripts/skills.py build                 # regenerate after editing a source
    python3 -I qat/scripts/skills.py check                 # stale generated files?
    python3 -I qat/scripts/skills.py check --base origin/main   # plus the version and eval gates
    python3 -I qat/scripts/skills.py package dist          # build the release bundle locally

## Version scheme

- **Skill version**: semver in each source's frontmatter. Bump patch for wording fixes that don't change behaviour, minor for added behaviour, major for changed output shape or removed behaviour. The ports from the installed skills start at `1.0.0`. `negative-space` keeps the version its text already declares, `0.1.0-reconstruction`. A `.qat.md` contract keeps its own `version:` (stress-test and truth-weight are at `2.0.0`), and the same bump rule applies to it.
- **Bundle version**: semver in `BUNDLE_VERSION`. This is the version you install and pin. It must go up whenever any generated skill changes (CI enforces this). A release is the git tag `qat-skills-v<bundle version>`.
- CI (`.github/workflows/qat-skills.yml`) fails a pull request when: a generated file is stale; a changed spec has no version bump; a changed spec has no eval run recorded in the same pull request (see CONTRIBUTING.md); or skills changed without a bundle bump.

## Releasing (maintainer)

1. Merge the change to `main`. Check that `BUNDLE_VERSION` holds the new version.
2. Tag that commit `qat-skills-v<version>` and push the tag.
3. `.github/workflows/qat-skills-release.yml` checks that the tag matches `BUNDLE_VERSION` and is on `main`. It then packages and attaches these files to a GitHub release:
   - `qat-kit-<version>.zip`: one Claude plugin (`.claude-plugin/plugin.json` plus `skills/<name>/…`);
   - `skills/<name>-<skill version>.zip`: one zip per skill (a `<name>/` folder with its `SKILL.md`), for apps that take single skills;
   - `skills.lock.json` and `SHA256SUMS`.

## Installing, updating, rolling back (Claude app)

The installed copies that exist today are separate per-skill uploads with the same names. Remove (or turn off) those first, so that two skills don't compete under one name.

1. **Install a pinned version.** Download `qat-kit-<version>.zip` from the GitHub release `qat-skills-v<version>`. Upload it where the app takes plugins or skills. If the app accepts only single skills, upload the per-skill zips you want. Any subset works, because the skills don't depend on each other to load.
2. **Check what you have.** Each installed `SKILL.md` names its version and source hash in its first body line. Compare them with `skills.lock.json` in the release.
3. **Update.** Upload the newer release's zip in place of the old one.
4. **Roll back.** Upload the older release's zip. Releases are never deleted or re-tagged, so every earlier version stays downloadable.

I haven't tested the exact upload screens and the names of the zip formats they accept. Confirm them on the first install, and correct this section in the same pull request as anything else.

## Pinning elsewhere (lanes, runners, other machines)

Pin the release tag. Either download the release zip for `qat-skills-v<version>`, or check out the tag and run `python3 -I qat/scripts/skills.py package dist`. Packaging is deterministic: the same tag gives the same `SHA256SUMS`.

## Optional by design

Nothing outside QAT-Kits requires these skills, and these skills require nothing outside QAT-Kits (DEC-193). Other Kairos instances, and anyone else, can install all of them, some of them or none. A skill that references a sibling skill (for example, thread-seed borrows selective-self-distillation's rules) names it as a reference. It does not load or call it.
