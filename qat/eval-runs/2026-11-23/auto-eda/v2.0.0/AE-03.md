I ran an EDA report on the payload. It holds 30 records under `data`. Flattened, that gives 2 columns, `a` and the nested `b.c`.

- **`a` is the integers 0 to 29**, each appearing exactly once (mean and median 14.5, no skew). It's numeric, so the report draws it as a histogram. In practice it behaves like a row index or ID, and the flat histogram just confirms that.
- **`b.c` alternates between "x" and "y"**, 15 of each (50/50). Even values of `a` have "x" and odd values have "y", so the two columns carry the same information.
- There are no missing values. With only one numeric column, there's no correlation grid.

In short, this looks like synthetic or test data rather than anything with real variation to analyse.

**Steps taken**
1. `mkdir -p <run dir> && cd <run dir>`
2. Wrote the pasted payload to a file: `python -c 'import json; json.dump({"data": [{"a": i, "b": {"c": "xy"[i % 2]}} for i in range(30)]}, open("payload.json", "w"))'`
3. `cp -r <skill_dir>/scripts ./auto_eda_scripts`
4. `python auto_eda_scripts/auto_eda.py payload.json --out eda_out` (it unwraps `data` and flattens `b.c`)
5. Read `eda_out/payload_eda.json` for the stats.
