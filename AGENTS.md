# AGENTS.md: working rules for coding agents in this repo

These rules apply to Claude Code, Codex or any other coding agent.

- **Claude skills: QAT-Kits is the source of record** (DEC-192, DEC-193, Zach 2026-11-10). For the skills listed
  in `qat/runtimes/claude/skills.lock.json`, the source is `qat/tools/<name>.skill.md` (and, for the `qat` runner,
  `qat/tools/*.qat.md`, `qat/cases/` and `qat/scripts/qat.py`). Edit the source, then run
  `python3 -I qat/scripts/skills.py build`. Never edit a file under `qat/runtimes/claude/` that carries the
  `GENERATED by qat/scripts/skills.py` stamp. See [qat/runtimes/claude/README.md](qat/runtimes/claude/README.md).
- **Eval-gated changes** (DEC-193). A spec changes only through a pull request that bumps its version, runs its eval
  cases and records the run under `qat/eval-runs/<date>/<name>/` (see [CONTRIBUTING.md](CONTRIBUTING.md)). CI
  (`qat-skills`) enforces the bump and the recorded run. Reviewers judge the run's content.
- **Optional by design** (DEC-193). The skills may not require another Kairos repository, and nothing outside this
  repo may require the skills. (The repo's own CI uses Telosmith; the skills do not.)
- **Open: stress-test and truth-weight have two texts here**, the standalone skill (`*.skill.md`, ported from the
  installed skill) and the runner contract (`*.qat.md`). They differ (drift inventory, U05-U11). Which one the
  standalone skill should be generated from is Zach's call. Until he decides, change neither to match the other.
- The other copies (`Toolkits/`, vault and ChatGPT copies; [docs/DRIFT_INVENTORY_2026-11-04.md](docs/DRIFT_INVENTORY_2026-11-04.md))
  are history. Do not edit them to "reconcile" them with the sources above.
- `qat/` holds the runner and the tool specs ([qat/PROVENANCE.md](qat/PROVENANCE.md)).
  Run from `qat/` (needs `pyyaml` and `jsonschema`): `python3 -I scripts/qat.py index` and
  `python3 -I scripts/qat.py eval cases/<tool>.eval.yaml <output dir>`.

## Records and ledgers

Two places hold reasons, and they do different jobs:

- **Records** (`.aec/records.jsonl`, [Telosmith](https://github.com/eraevous/Telosmith)) are the design truth
  inside this repo: its purpose (`P0`), the requirements behind the spec/contract machinery and the code that
  implements them (`implemented_by code:qat.scripts.qat...`). A record is provisional until Zach commits it
  (`"epistemic": "committed"`); agents may append provisional records and proposed decisions, never accepted ones.
- **Ledgers** (the relay-kit-private repository, `governance/decisions.jsonl` and `challenges.jsonl`) hold
  cross-repo coordination and the owner's decisions. Records cite their ids as text (for example
  `QAT-D-canon` cites DEC-048 and DEC-051).
- **Append only.** Never edit or delete an earlier line in `.aec/records.jsonl`. To change a record, append
  the same `id` with the next `version` and a `supersedes` relation.

After editing code, the Claude Code hook in `.claude/settings.json` runs `aec check` and `aec code-impact`
(it needs Telosmith installed at the commit pinned in `.github/workflows/telosmith.yml`; without it the hook
reports that and does not block). `[stale]` / `[needs_review]` means your change touched code a record relies
on; say in your summary whether the record still holds. The `telosmith` CI job runs the same check on every
pull request.
