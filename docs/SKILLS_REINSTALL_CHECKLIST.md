# Checklist: release qat-kit 1.1.0 and replace the installed skills

One-time migration from the skills uploaded one at a time to the release bundle built from this repo.
The general procedure (update, roll back, pin) is in
[qat/runtimes/claude/README.md](../qat/runtimes/claude/README.md); this is the concrete run for the first
release.

Who does what:
- **Zach**: merge, tag, and the upload/remove steps in the Claude app (agents can't upload or remove account skills).
- **Any agent** (a Kairos lane, or any Claude session): the checks before and after.

---

## Where the account stands (checked 2026-11-16)

- **14 custom skills come from this repo**, all installed as separate one-skill uploads:
  - braided-explanations, frame-shift, legal-ease, meta-distill, negative-space, qat,
    selective-self-distillation, stress-test, thread-map, thread-seed, truth-weight
  - auto-eda, mtg-deck-lab, zach-voice (added to the repo in the 1.1.0 change)
- **None carry the version stamp yet.** Their wording matches the repo except:
  - the Drive links the repo removed (stress-test, negative-space, and similar);
  - **qat**: the installed runner is older. It only has the stress-test and truth-weight contracts.
    1.1.0 adds effort-cost, kind-check, real-problem, thread-distill and toolsmith.
- **Not installed yet:** kind-check and real-problem as their own skills. They are hand-adapted runtimes and
  not in the bundle. The `qat` runner still runs their contracts.
- **5 custom skills come from relay-kit, not here** (chat-relay, chat-capture, chat-telemetry,
  handoff-ledger, relay-governor). Leave them alone in this migration.

## 1. Release (Zach)

- [ ] Merge the pull request that adds the three skills and bumps `BUNDLE_VERSION` to `1.1.0`.
- [ ] Check that `qat/runtimes/claude/BUNDLE_VERSION` on `main` reads `1.1.0`.
- [ ] Tag that commit and push the tag:

      git tag qat-skills-v1.1.0 <merge commit>
      git push origin qat-skills-v1.1.0

- [ ] Wait for the `qat-skills-release` workflow to finish. Confirm the GitHub release
      `qat-skills-v1.1.0` has:
  - `qat-kit-1.1.0.zip` (all 14 skills as one plugin)
  - 14 per-skill zips (`<name>-<version>.zip`)
  - `skills.lock.json` and `SHA256SUMS`

## 2. Download and verify (anyone)

- [ ] Download the assets into an empty folder.
- [ ] Check them:

      sha256sum -c SHA256SUMS

## 3. Pick the install form (Zach)

The README hasn't tested the upload screens yet. Try the plugin first:

- [ ] **Plugin**: upload `qat-kit-1.1.0.zip` where the app takes plugins.
  - If it's accepted, all 14 skills arrive together and update together from now on.
- [ ] **If plugins aren't accepted**: upload the 14 per-skill zips instead.
  - Any subset works; the skills don't depend on each other to load.
- [ ] Write down which form worked, and correct the README's "Installing" section in a follow-up pull
      request (the README asks for this on the first install).

## 4. Swap the old copies for the new (Zach)

Do this one skill at a time, or all at once if the plugin upload worked. Two skills with one name compete,
so never leave both turned on.

- [ ] Turn off (or remove) the old upload.
- [ ] Turn on the new one.
- [ ] Repeat for all 14:
  - [ ] braided-explanations
  - [ ] frame-shift
  - [ ] legal-ease
  - [ ] meta-distill
  - [ ] negative-space
  - [ ] qat
  - [ ] selective-self-distillation
  - [ ] stress-test
  - [ ] thread-map
  - [ ] thread-seed
  - [ ] truth-weight
  - [ ] auto-eda
  - [ ] mtg-deck-lab
  - [ ] zach-voice

Turning the old ones off rather than removing them leaves an instant rollback until step 5 passes.

## 5. Check what's installed (any agent, in a fresh session)

- [ ] List the account's skills. Each of the 14 shows up once, with no duplicates.
- [ ] Open each installed `SKILL.md`. Its first body line reads
      `GENERATED by qat/scripts/skills.py ... version: <v> · source sha256: <hash>`.
- [ ] Compare each version and hash with `skills.lock.json` from the release.
- [ ] Spot-check behaviour:
  - [ ] the `qat` runner lists 7 tools, including thread-distill and effort-cost;
  - [ ] auto-eda runs its script on a small synthetic CSV;
  - [ ] one QAT tool (e.g. stress-test) runs on a short idea.

## 6. Clean up (Zach)

- [ ] Once step 5 passes, remove the turned-off old uploads.

---

## Rolling back

- Turn the old copies back on (if not yet removed), or upload the per-skill zips from an earlier release.
- Releases are never deleted or re-tagged, so `qat-skills-v1.0.0` stays available.
  - Note: 1.0.0 was never tagged. If the first tag is 1.1.0, the only rollback is the old uploads,
    so keep them until step 5 passes.

## What can wait

- **Nothing breaks if this waits.** The installed copies keep working. You just run the older `qat` runner
  and can't tell installed versions apart.
- **What depends on it:** using the newer runner contracts (thread-distill, effort-cost, kind-check,
  real-problem, toolsmith) through the `qat` skill. Also the rule that QAT-Kits is the source of record for
  Claude's QAT skills (10 Nov 2026): until the swap, what's installed isn't what's recorded here.
