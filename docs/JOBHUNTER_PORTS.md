# JobHunter companion ports: design and historical behavior

Candidate versions: ResumeTailor, InterviewCommander and ReflectiveJobNote **0.1.0**. These are independently invoked chat tools with native QAT contracts, matching standalone skills and ChatGPT paste blocks. No model/provider SDK, service, database or new runtime dependency is added. ToolSmith's contract-first, failure-first approach guided the port; legacy files are design inputs, not accepted contracts or validation evidence.

This stack is based on parser PR #37 at `220cdbdcbdcd42ecea78fb7cfab9e3d0e1a66a8e`. It does not alter that PR, its branch or any parser source, case, exemplar or test. Its base is `feat/jobhunter-dossier`, not main. Review the parser independently; rebase/retarget the companion stack only after the owner decides how to land the base. Nothing is merged by this work.

## Contract and provenance choices

Each `.qat.md` is the authoritative procedure for its port. `.skill.md` and `.paste.md` carry identical procedure text; tests enforce parity. Claude skills and the runner bundle are generated by the existing `skills.py` path. This duplicates adaptation text under existing conventions, not the tool logic in a new runner. No legacy source, existing runner implementation or design record is changed.

Every output section uses QAT's existing `claims` type (bullet lists). A cover letter is paragraph bullets plus source notes; a consumer must remove provenance notes only after reviewing them, never silently certify them. The runner audits headings and list shape, not factual grounding or inference quality.

Required input names are deliberately small: `evidence` for tailoring, `target` for preparation, `notes` for reflection. Runtime procedures handle blank/insufficient input without invented facts. The CLI audits outputs and does not enforce input sufficiency or generate a model response. Optional `context` accepts user priorities or a derived artifact with source IDs; it never becomes independent corroboration. No handoffs are registered, so the contract does not imply a mandatory sequence or automatic action.

## Acceptance evidence and limits

Each port includes five fictional cases and authored exemplar outputs, spanning cold use, the central failure mode, optional fallible prior output, thin input and prompt injection. ResumeTailor also exercises requested versus absent cover-letter consent; InterviewCommander exercises actual draft-answer feedback and one-turn rehearsal; ReflectiveJobNote exercises approximate recollection and a criterion correction.

The tests audit all 15 exemplars, reject every missing required section, check identical provider procedures and six employer-assessment axes, and reject 11 deliberate fixture mutations. One mutation exposed an overly broad résumé regex: it matched “Assisted” in the later evidence annotation even after the rewritten verb became “Led.” The check now anchors the intended wording immediately after `After:`; the mutation fails as intended. This improves the mechanical test without claiming a general factuality validator.

All **30 semantic criteria remain ungraded**. The outputs were authored by the implementer, not produced by cold model execution. Independent semantic runs, cross-provider behavior, installation UI behavior, independent review and fresh-context execution review remain outstanding. See [verification](../qat/eval-runs/2026-11-23/JOBHUNTER_COMPANIONS_VERIFICATION.md). No paid model call was made to simulate completeness.
